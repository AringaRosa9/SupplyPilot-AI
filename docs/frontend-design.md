# SupplyPilot AI 前端页面与布局方案

> 状态：Approved（2026-08-11）
> 目标：先确定 MVP 的信息架构、页面布局和核心演示动线，暂不拆开发计划。

## 1. 设计结论

SupplyPilot AI 不应设计成“左侧十几个菜单 + 每页一排指标卡”的传统管理后台。MVP 更适合采用 **活动主线 + 决策工作台 + 上下文 Intelligence Agent** 的结构：用户始终知道当前活动是否准备好、哪里有缺口、为什么有风险、下一步该做什么。

整体体验关键词：**专业、克制、可信、可解释、行动导向**。

### 推荐的产品壳层

- 左侧主导航：5 个高频工作区，保持稳定。
- 顶部上下文栏：全局搜索、活动范围、市场/产线筛选、通知、角色切换。
- 中央工作区：承载列表、分析和业务操作。
- 右侧 Intelligence Rail：按需展开的 Agent，上下文跟随当前活动、商品或风险。

## 2. 信息架构

### 一级导航

1. **驾驶舱**：跨活动的风险、进度和待决策事项。
2. **招商活动**：活动创建、详情、任务、提交与复盘。
3. **货品池**：全局商品状态、校验、评级和审核。
4. **供给洞察**：供给缺口、货盘健康度和供应商分析。
5. **自动化**：规则、执行记录、失败重试和通知。

### 全局入口

- **Intelligence Agent**：顶部按钮打开右侧栏；需要深度分析时进入完整工作台。
- **通知中心**：集中展示临期、失败、供给不足和集中度风险。
- **角色切换**：用于 MVP 演示不同角色看到的默认视图和可执行操作。

### 页面归并

| PRD 页面 | 方案中的位置 |
|---|---|
| 登录与角色切换 | 轻量登录页 + 顶部角色切换器 |
| 全局供应链驾驶舱 | 驾驶舱 |
| 招商活动列表 | 招商活动 / 列表 |
| 活动详情与招商进度 | 招商活动 / 活动详情 |
| 创建招商活动 | 招商活动 / 创建流程 |
| 商品提交与校验结果 | 活动详情 / 商品导入流程 |
| 全局货品池 | 货品池 |
| 商品评级详情 | 货品详情页；快速查看使用侧边层 |
| 供给缺口分析 | 供给洞察 / 缺口 |
| 供应商分析 | 供给洞察 / 供应商 |
| Product Line Intelligence Agent | 全局右侧栏 + 完整工作台 |
| 自动化规则中心 | 自动化 |
| 活动与产线复盘报告 | 活动详情 / 复盘 |

## 3. 全局布局

### 桌面端基准

MVP 优先服务桌面端数据工作，建议以 1440px 设计稿为基准，并保证 1280px 可正常使用。

```text
┌──────────────┬────────────────────────────────────────────────────┐
│ SupplyPilot  │ 搜索  当前活动/市场/产线       Agent  通知  角色   │
├──────────────┼────────────────────────────────────────────────────┤
│ 驾驶舱       │ 面包屑 / 页面标题                         主操作    │
│ 招商活动     │ ────────────────────────────────────────────────   │
│ 货品池       │                                                    │
│ 供给洞察     │                主工作区                            │
│ 自动化       │                                                    │
│              │                              ┌──────────────────┐  │
│              │                              │ Intelligence Rail│  │
│ 帮助与口径   │                              │ 按需展开         │  │
└──────────────┴──────────────────────────────┴──────────────────┘  │
```

### 尺寸建议

- 左侧导航：224px，支持收起到 72px。
- 顶部栏：64px，页面滚动时保持可见。
- 页面水平留白：24–32px；主要分区间距 32–48px。
- Agent 侧栏：默认关闭，展开宽度 400–440px。
- 内容不强制限制为窄容器；表格和分析页应充分利用横向空间。

### 导航原则

- 一级导航只表达业务空间，不把“评级详情”“导入结果”等任务步骤放进去。
- 活动详情内部使用页签承载：概览、招商任务、活动货品、风险、复盘。
- 当前活动是强上下文，切换活动后，洞察和 Agent 默认继承该范围。

## 4. 核心页面布局

## 4.1 全局驾驶舱

驾驶舱的第一屏不以大数字为主，而以“今天需要处理什么”为主。

```text
┌──────────────────────────────────────────────────────────────────┐
│ 供应链驾驶舱                         时间范围 / 市场 / Hotel+Flight│
│ 今天有 6 项需要决策 · 2 项会影响东南亚暑期旅行节                 │
├───────────────────────────────────────┬──────────────────────────┤
│ 决策队列（7/12）                      │ 货盘健康趋势（5/12）      │
│ P0 曼谷酒店供应商集中度过高           │ 总分 74 / 较上周 -6       │
│ P1 上海—普吉库存缺口 38%              │ 趋势线 + 维度扣分排序      │
│ P1 12 个商品等待审核                  │ [查看计算口径]             │
├───────────────────────────────────────┴──────────────────────────┤
│ 活动准备度时间轴：目标 → 已招商 → 已校验 → 高评级 → 已上架       │
├───────────────────────────────────────┬──────────────────────────┤
│ 市场 × 产线供给覆盖矩阵               │ Agent 今日建议             │
│ 用色块和数字标出缺口，不仅依赖颜色     │ 结论 / 依据 / 推荐行动      │
└───────────────────────────────────────┴──────────────────────────┘
```

关键交互：

- 点击风险直接进入已带好筛选条件的活动、货品池或洞察页。
- 健康度可展开维度得分、扣分原因、口径和更新时间。
- Agent 建议只能先进入“行动预览”，确认后才能创建任务。

## 4.2 招商活动列表

这是业务工作入口，采用“少量汇总 + 主表格”，不使用活动卡片墙。

- 顶部：页面标题、创建活动、视图切换（进行中/待启动/已结束）。
- 状态摘要条：进行中、临期、有风险、待复盘，仅作快速过滤。
- 主表字段：活动、目标市场、产线、阶段、准备度、关键缺口、截止时间、负责人。
- 每行直接显示一个最重要的阻塞问题；其余信息在展开行中查看。
- 支持保存视图，例如“我负责的”“5 天内截止”“Hotel 风险活动”。

## 4.3 创建招商活动

不使用弹窗，采用独立三步流程：**描述需求 → 确认结构化条件 → 预览任务**。

```text
┌──────────────────────┬───────────────────────────────────────────┐
│ 1 描述需求           │ AI 结构化结果                             │
│ 2 确认条件           │                                           │
│ 3 预览任务           │ 目标市场  中国 / 新加坡 / 澳大利亚        │
│                      │ 产线      Hotel / Flight                  │
│ 活动名称             │ 日期      2026-07-01 ～ 2026-08-31        │
│ 自然语言需求         │ 条件      四星以上 / 亲子 / 价格优势 5%   │
│ [粘贴历史活动要求]   │                                           │
│                      │ 需要确认：上海—普吉库存目标尚未填写        │
│                      │                          [保存草稿][继续]  │
└──────────────────────┴───────────────────────────────────────────┘
```

设计重点：

- AI 不确定字段用明确的“待确认”区呈现，不自动填入猜测值。
- 结构化结果可逐字段编辑，并保留自然语言原文作为来源。
- 最后一步展示即将创建的 Hotel / Flight 任务、负责人和规则摘要。

## 4.4 活动详情

活动详情是 MVP 的核心页面，应该承载完整业务主线。

### 固定页头

- 活动名称、状态、负责人、截止时间。
- 准备度主进度：招商目标 → 提交 → 校验 → 评级 → 上架。
- 右侧主操作随阶段变化，例如“导入商品”“处理待审核”“生成复盘”。

### 页签

1. **概览**：关键阻塞、进度、供给目标、最近动态。
2. **招商任务**：Hotel / Flight 任务树、负责人、完成度和临期状态。
3. **活动货品**：已自动限定当前活动的货品池视图。
4. **风险**：供给缺口、供应商集中度、异常库存和价格变化。
5. **复盘**：活动结束后出现；未结束时展示复盘所需数据的完整度。

概览页建议使用 8/4 分栏：左侧是活动准备度和任务进展，右侧是风险与动态。风险始终排在普通动态之前。

## 4.5 商品导入与校验

采用全页导入流程，不把复杂结果塞入弹窗。

步骤：**上传文件 → 字段映射 → 自动校验 → 处理问题 → 提交入池**。

- 左侧显示步骤和每步状态。
- 中央使用虚拟化数据表呈现商品数据。
- 右侧问题面板按“阻塞 / 需补充 / 疑似异常”分组。
- 点击问题后定位到具体行和字段。
- 顶部始终展示通过数、阻塞数、警告数和剩余待处理数。
- 支持只提交通过项；失败项可下载带原因的 CSV。

## 4.6 全局货品池

货品池是高密度工作页，应以表格为核心，而不是产品卡片。

### 顶部区域

- 范围：活动、产线、市场。
- 保存视图：待审核、高分待上架、评级失败、库存风险。
- 操作：导入、批量审核、重新评级；批量操作只在勾选后出现。

### 表格字段

- 商品、产线、活动、市场/城市或航线、供应商。
- 当前状态、评级、综合分、置信度。
- 价格竞争力、库存健康度、风险标签、更新时间。

点击商品默认打开快速查看侧边层；需要审阅完整依据时进入商品详情页。

## 4.7 商品评级详情

页面回答四个问题：**得分多少、为什么、数据可靠吗、下一步做什么**。

```text
┌───────────────────────────────────────┬──────────────────────────┐
│ 曼谷河畔酒店 · Hotel                 │ 评级 A · 86               │
│ 当前状态：待审核                      │ 置信度 0.91                │
│ [建议上架] [要求补充信息] [驳回]      │ 模型 Hotel v1.2            │
├───────────────────────────────────────┴──────────────────────────┤
│ 评分贡献：价格 +24 / 转化 +16 / 库存 +17 / 服务 +12 / ...       │
│ 风险扣分：供应商取消率偏高 -6                                  │
├───────────────────────────────────────┬──────────────────────────┤
│ 维度证据与原始数据                    │ Agent 解释                 │
│ 指标 / 当前值 / 对比基准 / 更新时间    │ 结论 / 限制 / 改进建议      │
├───────────────────────────────────────┴──────────────────────────┤
│ 状态与评级时间线：输入版本、模型版本、操作者、变更原因           │
└──────────────────────────────────────────────────────────────────┘
```

不建议用雷达图作为核心解释，因为难以精确比较。更适合使用按权重排序的贡献条、基准对比和证据表。

## 4.8 供给洞察

使用同一分析工作区承载三个视图：**供给缺口、货盘健康、供应商**。

### 供给缺口

- 首屏是目标与当前供给的差异矩阵，维度可在城市/航线、价格带、客群间切换。
- 右侧为缺口优先级列表，展示缺口规模、剩余时间和业务影响。
- 选择一个缺口后，在下方展开趋势、关联任务和 Agent 招商建议。

### 货盘健康

- 总分只是入口，主要区域展示六个维度的趋势和扣分来源。
- 支持比较 Hotel 与 Flight、不同市场和不同活动。
- 每个异常点都能追溯到具体商品或供应商。

### 供应商

- 上半部分展示 HHI、Top 供应商占比和集中度趋势，并附计算范围与阈值。
- 下半部分是供应商表现矩阵：履约率、取消率、转化、库存稳定性和覆盖市场。
- 供应商详情使用完整页面，展示跨活动长期表现，不绑定某一次活动。

## 4.9 Intelligence Agent

Agent 不是孤立聊天页，而是全局可调用的分析层。

### 右侧 Intelligence Rail

- 自动带入当前页面上下文，例如活动、商品、筛选条件和时间范围。
- 顶部明确显示“正在分析什么”，允许移除上下文。
- 回答固定分为：结论、数据依据、风险与限制、推荐行动、置信度。
- 数据依据可点击，跳转到对应表格或图表并保持筛选条件。

### 完整工作台

适合复杂问题，采用 7/5 分栏：

- 左侧：对话、追问、建议问题。
- 右侧：查询范围、证据表、图表、行动预览和历史建议。
- “创建招商任务”等写操作必须先生成差异预览，再由用户确认。

## 4.10 自动化规则中心

页面分为：规则列表、执行记录、失败任务。

- 规则列表使用紧凑表格，展示触发条件摘要、状态、版本、最近执行和成功率。
- 规则详情使用接近自然语言的条件编排：当……且……则……。
- 编辑区左右分栏：左侧配置条件和动作，右侧实时显示规则解释与模拟命中结果。
- 启用新版本前展示影响范围，失败记录提供原因、相关实体和重试入口。

## 4.11 复盘报告

复盘不做成普通仪表盘，而做成可阅读、可导出的叙事报告：

1. 本次活动是否达成目标。
2. 缺口从开始到结束如何变化。
3. 不同等级商品的实际转化表现。
4. 哪些供应商拉高或拖累了结果。
5. 评分与实际表现是否一致。
6. 下次活动应调整哪些招商策略。

每个章节都使用“结论句 + 关键图表 + 数据口径 + 可执行建议”的结构。

## 5. 视觉语言

### 色彩角色

- 主品牌色：深海军蓝，用于关键按钮、选中态和重要标题。
- 页面背景：带轻微蓝色倾向的暖白；内容表面只做一级区分。
- 健康/完成：低饱和绿色，同时配合图标和文字。
- 关注/临期：琥珀色。
- 阻塞/高风险：砖红色，避免大面积铺满。
- 图表：以主蓝为基准，只在语义需要时使用绿、黄、红。

### 字体与数字

- 中文正文优先使用高可读性的无衬线字体；英文和数字可使用 Instrument Sans 或同类人文无衬线字体。
- 页面标题约 28px，分区标题 20px，正文 16px，表格和辅助信息 14px。
- 所有指标和表格数字启用等宽数字特性，便于纵向比较。
- 不使用超大指标数字制造“驾驶舱感”，重点通过层级、位置和留白建立主次。

### 组件风格

- 圆角适中，建议 8–10px；表格、筛选和状态条可更克制。
- 阴影只用于浮层、下拉菜单和 Agent Rail，普通内容区使用间距和分隔线分组。
- 状态标签必须同时包含文字，不能只依赖颜色。
- 图表旁固定提供口径、时间范围和最后更新时间。

## 6. 响应式范围

- 桌面端（1280px 以上）：完整工作台，优先实现。
- 平板（768–1279px）：导航收起，双栏变单栏，Agent 作为覆盖式侧栏。
- 手机端：MVP 只保证查看通知、审批和风险处理；复杂导入、规则编辑和深度分析提示前往桌面端。

## 7. MVP 核心演示动线

建议演示只走一条连续主线：

```text
驾驶舱发现东南亚活动风险
→ 进入活动详情
→ AI 结构化招商需求并生成 Hotel / Flight 任务
→ 导入商品并处理校验问题
→ 在货品池查看评级
→ 打开商品详情解释 86 分与风险扣分
→ 供给洞察发现曼谷供应商集中度过高
→ Agent 生成补充招商任务预览
→ 用户确认创建任务
→ 活动结束后查看复盘建议
```

这条动线能够在 3–5 分钟内同时展示业务闭环、可解释评分、Agent 受控操作和自动预警，是前端实现时应优先保证的体验。

## 8. 暂缓项

为了控制 MVP，不建议首版投入：

- 独立的复杂权限管理后台。
- 完整自定义仪表盘。
- 多主题和完整暗色模式。
- 移动端全功能编辑体验。
- 高自由度拖拽式自动化编排器。
- 过多地图和装饰性数据可视化。
